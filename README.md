# 사과 깎기 — 3단계 (2026-10-15~16: 연속 껍질 리본) · 이전: 3차 수정(칼 범위·Q/E 기울기·좁은 활성 구간)

세로형 모바일 웹 미니게임. 세로 중심축을 따라 자동 회전하는 로우폴리 사과(Three.js) 오른쪽에 과도(제공 PNG)가 세워져 있고,
플레이어가 방향키/하단 패드로 칼을 움직이고 기울여 **회색 날의 짧은 활성 구간**으로 껍질을 깎는다.
1단계(회전·배치·조작·UI) → 2단계(절삭) → **3차 수정**(사용자 플레이 피드백 4건). 회전 방향·그래픽·사과/칼 배치·UI·방향키는 사용자 승인 상태 그대로.
명세 정본은 `GAME_SPEC_APPLE_PEELING.md`(사용자 원문), 공통 규칙은 `MINIGAME_SYSTEM.md` / `MINIGAME_BUILD_TEMPLATE.md`.

## 실행 방법

- `index.html` 더블클릭(file://)으로 바로 열린다(칼 PNG base64 내장, Three.js 는 `vendor/three.min.js`). 빌드·서버 불필요.
- 폰: `node tools/serve.js` → 같은 와이파이에서 `http://<PC-IP>:8080/` (방화벽은 BUILD_TEMPLATE §7-4).
- 흐름: **시작 화면 → [시작하기] → 플레이(60초, HUD: 남은 시간·껍질 제거·과육 손실) → [완료] 또는 시간 종료 → 결과 화면(최종 사과) → [다시 깎기]**.
- 조작: PC `← →`(사과 쪽/반대쪽) `↑ ↓`(높이) **`Q`(반시계) `E`(시계) 기울기**. 모바일 패드: 왼쪽 엄지 [↶ ↷] / [← →], 오른쪽 엄지 [↑ / ↓]. 버튼마다 손가락을 따로 잡아 동시 조합 가능.
- 디버그: `index.html#debug` — 표면 마커 · 날 폴리라인(빨강) · 등/힐(회색) · 칼날/연결부/손잡이 다각형 · 칼 쪽 자오선(파랑) · **절삭 중인 행 눈금 + 절삭점 X(초록)** · 좌상단 읽기(섹터·기울기·중심 행·깊이·셀 집계·조각 수·배율).
  콘솔: `AP_DEBUG.logCuts(true)` · `AP_DEBUG.dumpSurface()` · `AP_DEBUG.cellStats()` · `AP_DEBUG.cellsAt(섹터)` · `AP_DEBUG.cellState(행, 섹터)` · `AP_DEBUG.contact()` · `AP_DEBUG.chips()`.
- 헤드리스 QA: `node tools/qa.js`(1단계 회귀) · `node tools/qa-cut.js`(절삭) · `node tools/qa-v3.js`(범위·기울기·피드백) · 모두 `--shots <폴더>` 가능. PNG 를 바꿨을 때만 `node tools/build-assets.js`.

## 네 문제의 원인과 수정

**1. 칼이 아래까지 안 내려감** — 세로 한계를 PNG 전체 bbox 로 HUD 아래~패드 위에 가두고 사과를 플레이 영역 정중앙에 둬서, 손잡이(칼 길이의 65%) 때문에 팁이 바닥에 못 닿았다.
→ 한계를 **절삭점(피벗) 기준**으로(능선 −4px ~ 바닥 +4px), 이미지는 HUD/패드와만 안 겹치게. 사과 세로 위치는 "기울기 0 의 칼 절삭점이 능선~바닥 전체에 닿는 방"(칼 위~피벗 + 몸통 + 피벗~칼 아래)을 플레이 영역에 맞춰 정한다(390×844: 필요 472 / 가용 611 → 배율 1, 사과 중심 y 365 → 301). 방이 모자라는 320×568 은 사과·칼을 0.95 배로 같이 줄인다.
가로 한계는 **날만 화면 안**: 이미지 전체를 가두면 Q 로 기울이는 순간 오른쪽으로 휘어 나간 손잡이가 벽에 닿아 칼 전체가 사과 속으로 떠밀리는 버그가 있었다(추적으로 확인). 손잡이는 화면 밖 허용(요청 사항).

**2. 칼 각도** — `Q` 반시계 / `E` 시계, 0° 시작, ±40°, 60°/s 램프업(0.05s)·떼면 즉시 정지. 피벗 = 날 폴리라인의 55% 지점(곧은 부분 시작 = 절삭점). 이미지와 절삭선은 같은 `toStage()` 변환(QA: 모서리 불일치 < 0.01px). ←→↑↓ 는 피벗을 옮기므로 기울기와 독립.
기울기의 역할: 어깨에서 날을 표면 경사에 평행하게(위쪽 어깨 Q, 아래쪽 E) 두어야 활성 구간 안 행이 고르게 깎인다. 세워 두면 넓은 쪽 행이 더 깊이 파인다.

**3. 즉시 피드백** — 절삭은 오른쪽 실루엣(월드각 0)에서 일어나고 정면 표면은 왼쪽→오른쪽으로 돌기 때문에, **막 깎인 셀은 바로 뒤로 넘어간다(물리 그대로)**. 이것은 좌표 변환 버그가 아니라 "칼은 오른쪽, 정면은 오른쪽으로 이동"의 귀결이다. 깎이는 셀이 지금 칼 앞 섹터이고 그 셀의 화면 위치가 그 높이의 날 위치와 같다는 것을 QA 로 확인했다(±1px). 뒤쪽 표면을 바꿔 앞에서 깎이는 척하지 않았다.
그래서 접촉점에 **즉시 보이는 것**을 넣었다: ① 껍질 조각(새 껍질이 실제 제거된 프레임에만, 이미 깎인 곳에서는 생성 없음 — QA 로 확인) ② 실루엣의 홈(메시 변형) ③ HUD 제거율 같은 프레임 반영 ④ 위에서 18° 내려다보는 카메라라 윗반쪽은 실루엣을 지난 뒤에도 보인다. 크림색 표면이 칼 바로 옆에서 "앞쪽에" 나타나게 하려면 회전 방향을 뒤집거나 칼을 왼쪽에 둬야 하는데, 둘 다 유지 대상이라 바꾸지 않았다.

**4. 너무 넓은 띠** — 직선 날이 둥근 몸통과 겹치는 모든 행(40~60px)을 깎았다.
→ **활성 절삭 구간** = 피벗 높이 ±12px(`CUT.WINDOW_HALF`) 이면서 피벗 행과 원래 반경 차 ≤ 12px 인 행만. 같은 높이에 두면 8~24px 띠, 천천히 내리면 나선. 구간 밖 행은 날이 겹쳐도 깎지 않는다(QA: 겹치는 10행 전부 무접촉). 급경사(능선·바닥)에서는 반경 조건으로 구간이 저절로 좁아져, 40° 한계로 못 따라가는 곡률에서도 이웃 행을 파지 않고 끝까지 깎을 수 있다.

## 현재 한계 · 다음 개선 포인트

- 즉시 "크림색이 칼 옆에서 보이는" 연출은 회전 방향·칼 위치를 유지하는 한 물리적으로 불가(위 3번). 리본(3단계)이 접촉점 피드백의 본체가 될 예정.
- 능선 2행(r 49→57px, 경사 66°)은 ±40° 로는 날이 못 따라가지만, 반경 조건으로 구간이 46~47행만 남아 이웃 행을 파지 않고 깎인다. 그래도 9px 이상 밀어 넣어야 하므로 가장 어려운 구간이다.
- 손잡이가 화면 오른쪽 밖으로 나갈 수 있다(요청대로). 기울인 채 → 끝까지 가면 손잡이 일부가 잘려 보인다.
- 홈의 벽(경사면)은 이웃 셀 색(빨강). 리본과 함께 코너 단위 색 검토.
- 미구현: 리본·효과음(3단계), 점수·결과 수치·저장(4단계).

## 절삭 애니메이션 완성도 개선 (2026-10-16)

판정·회전·배치·조작·UI·집계는 건드리지 않았다(전 QA 통과). 바뀐 파일: `ribbon.js`(움직임·렌더), `apple.js`(경계 렌더), `config.js`(`RIBBON` 값), `main.js`(`AP_DEBUG.setSmoothPeel`), `tools/qa-polish.js`(신규).

- **시작점**: 머리 = 새로 벗겨진 셀의 무게중심 = 그 높이의 날 엣지 위(QA: 기울기 −40/0/25/40° 모두 머리↔셀 위치 0.000px, 머리↔날 폴리라인 ≤ 0.07px). 날 구간에서는 마디가 엣지 안쪽(칼 몸통)으로 못 들어가도록 눌러(`BLADE_CLEAR`) 옆면에 붙어 보이지 않고, 칼(renderOrder 10) 아래에 그려 손잡이 위로 지나가지 않는다.
- **움직임**: 갓 분리된 처음 8마디는 날 엣지 접선 + 날에서 멀어지는 법선 방향으로 들려 아치(≈20px)를 만든 뒤 중력으로 처진다. 사슬의 뒤쪽 40%는 끝이 안쪽(사과 쪽)으로 말리고, 마디 평활·굽힘 완화로 톱니를 없앴다(마디 간 최대 꺾임 14° < 35°). 비틀림은 약 100px 간격으로 한 번 뒤집히는 일부 구간뿐(계속 도는 나선 아님). 폭 6 → 4.8px(−20%), 겉면 빨강/안쪽면 옅은 붉은색. 속도 감쇠 0.97로 출렁임 억제, 늘어나지 않는 줄. 칼이 움직이면 머리만 따라가고 몸통은 뒤따른다.
- **끊김·낙하**: 조건 동일(0.2s). 낙하 리본에도 말림 힘이 걸려 구부러지며 떨어지고, 프레임당 마디 이동 ≤ 4.2px(순간이동·소멸 없음).
- **절삭 경계**: 계단의 원인은 셀 하나가 통째로 한 색이던 것(판정 셀 96×48 자체는 메시 해상도와 같아 변경 불필요). 판정·정점은 그대로 두고, 정점별 "벗겨진 비율"(코너를 공유하는 셀 평균)을 삼각형 안에서 보간해 0.5 등치선으로 자르는 셰이더로 바꿨다(화면 미분 폭만큼만 안티앨리어싱, 블러 아님). 경계가 셀 안을 대각선으로 지나며 회전해도 안정(미세 회전 2차 차분 0.356 일정). 지표: 열 사이 2px 이상 점프 비율 0.004 → 0.000, 2차 차분 0.424 → 0.356. 개선 폭은 작다(정렬된 가로 띠 경계는 원래 계단이 적고, 대각선 구간과 띠 끝에서 차이가 난다 — `screenshot/phase4_boundary_*.png` 비교). `AP_DEBUG.setSmoothPeel(false)` 로 이전 셀 단위 렌더로 되돌려 비교 가능.

## 4단계 — 게임성·난이도·점수 밸런스 (2026-10-16)

회전 속도(2.5s)·제한 시간(60s)·사과/칼 그래픽·조작·리본 애니메이션·UI 는 그대로. 새 파일 `scoring.js`, `tools/qa-balance.js`. 수정: `cutting.js`(깊이 단계·손실 지수) · `apple.js`(지수 집계) · `ribbon.js`(경로 단절) · `play.js`/`main.js`/`index.html`/`main.css`(결과 화면에 점수 표시) · `config.js`.

- **진단**: 과육 손실이 거의 안 나던 이유는 정확히 깎아서만이 아니라 판정이 관대해서였다. 껍질 두께 7px 라 "껍질만" 깊이 구간이 넓었고(정확/대충 플레이 모두 손실 ≈ 0%), 손실은 몸통 부피로 나눠 작게 보였다.
- **깊이 4단계**(껍질 두께 skin 기준, 반경 방향·사과 실제 반경과 절삭점으로 계산): 1 미접촉 / 2 얕음 d<0.25·skin(긁힘, 제거 아님) / 3 적정 0.25·skin≤d≤skin(껍질만) / 4 깊음 d>skin(과육 손실). `contact.tier`·`depthRatio` 로 노출(디버그 읽기).
- **과육 손실**: e = 껍질 아래로 들어간 깊이. 손실 부피 = Σ면적×e(파임 메시와 일치) · 손실 지수 = Σ면적×(e + e²/8) 를 몸통 부피로 나눈 %(깊을수록 빠르게 증가, 현재 표면 깊이 기준이라 같은 곳 중복·접촉 시간과 무관). 껍질 두께 7→4px.
- **연속 껍질**: 새 껍질이 0.2s 안 나오거나, 절삭점이 한 프레임에 36px 이상 튀면(경로 불연속) 끊김. 깊이만으로는 끊기지 않음. 기록은 새 껍질 경로만 누적(반복 통과로 못 부풀림).
- **점수**: `score = clamp(0.8·제거율 + min(20, 최장cm/8)·clamp(제거율/60,0,1) − 4·손실지수%, 0, 100)` 반올림. 테스트안(감점 3)을 4 로, 보너스에 제거율 게이트를 추가. 구간 문구는 명세 그대로(90/75/50/그 이하). 상수 전부 `config.js SCORE`.
- **테스트(`node tools/qa-balance.js`, 60초)**: A 정확 95점(제거 93.5%·손실 0%·320cm) · B 깊게(2×) 37점(손실 15%) · C 가만히 4점(제거율 4.6% 에서 정체) · D 빠르게 위아래 3점 · D′ 너무 빠른 하강 27점 · E 정교한 나선 95점 · 평균 모델 95 · 초보 모델 89(손실 1.8%). 하강 속도 스윕: 13px/s 63점 → 8px/s 91점 → 4.6px/s 95점(너무 빠르면 껍질이 남음).
- **남은 문제**: 숙련도 차이가 점수 상단(89~96)에서 좁다 — 시간이 넉넉해 완성도가 포화(제한 시간·회전 속도 조정 후보, 이번엔 유지). 자동조종 기반 수치라 실제 사람 플레이로 재조정 필요. 결과 저장 이미지·효과음 미구현. 아랫부분은 곡면 자체로 어려워지며(반경 급감) 별도 감점은 없다.

## 절삭 정밀도·폭 조정 (2026-10-16)

- **기존 폭**: 활성 절삭 구간 반폭 `CUT.WINDOW_HALF` 12px(구간 24px)이고 셀 행 간격은 약 3.8px. 판정 폭과 화면 표시 폭은 같은 셀 데이터를 쓰므로(경계 셰이더는 색만 보간) 둘이 다를 수 없다 — 그래픽만 얇게 만드는 일은 하지 않았다.
- **설정**: `CUT.WIDTH_SCALE`(기본 **0.8**)가 구간을 줄인다. 비교 도구 `node tools/qa-width.js`가 100/85/80/75%를 같은 시나리오로 측정.
- **측정(고정 높이 한 바퀴, 적정 깊이 0.6×껍질)**: 구간이 실제로 제한하는 곳은 가장 넓은 적도뿐이다. 윗/아랫부분은 곡면 때문에 이미 4~8px 띠(깊이 조건이 먼저 제한). 적도 띠: 100% 23px(제거 15.2%) → 85/80/75% 모두 19px(12.7%, −17%). 85/80/75가 같은 이유는 행 간격 3.8px 의 이산화(±2행 구간이 반폭 7.6~11.4px 에서 동일).
- **선택 80%**: 그 평탄 구간(7.6~11.4px)의 가운데(9.6px)라 행 이산화에 가장 안전하고, 요청 범위(75~85%)에 든다. 60초 결과(하강시간 22/32/40s): 100% 84/92/94% · 80% 76/92/92% — 느슨한 하강(≤5.7px/s)에서는 같고 빠른 하강(8px/s)에서만 껍질이 더 남는다(판정을 관대하게 만들지 않음). 폭 80%에서 60초 안에 92%/93점 달성 가능.
- **곡면**: 윗·아랫부분은 구조 변경 없이 기존 곡면 판정을 유지(껍질 두께의 경사 환산 ≤2배로 윗부분 여유, 반경 조건으로 급경사에서 구간 자동 축소). 아랫부분: 기울기 0°에서 행0~5 제거 12셀 → +40° 맞추면 60셀, 과도한 깊이는 과육 손실 15.8%.
- **리본**: 자동조종 나선에서는 27초(내려가는 동안)·5,370px 한 줄로 끊김 없이 이어졌고 끊김은 하강이 끝난 뒤(껍질이 더는 안 나올 때)뿐이었다. 끊김 허용(`BREAK_GRACE`) 0.2→0.3초, 폭 4.8→5.2px(실처럼 보이는 구간 완화). 끊김 원인 기록(`ribbon.log`: grace/jump).
- **실제 사람 조작감은 확인하지 못했다**(자동 시뮬레이션만).

## 긴급 수정: 칼을 떼도 게임이 끝나지 않던 버그 (2026-10-16)
- **원인**: main.js 가 시작할 때 QA 호환 모드를 켠 채(`AP.play.setQaMode(true)`) 배포돼, play.js 의 이탈 종료 검사(`!S.qa && noContactT > 150ms`)가 제품에서 항상 꺼져 있었다. 실제 브라우저에서 칼을 3초 넘게 떼어도 상태가 PLAYING 으로 남았고(`qa:true, contact:false, noMs 3266`), 결과 화면도 열리지 않았다.
- **왜 그동안 못 잡았나**: 이전 테스트는 매번 `AP_DEBUG.setLegacy(false)` 로 실제 규칙을 먼저 켠 뒤 돌렸다(제품 기본값을 한 번도 검사하지 않음).
- **수정**: 제품 기본 = 실제 규칙(`qaLegacy=false`). 호환 모드(시작 즉시 PLAYING·종료 없음)는 테스트가 `setLegacy(true)` 로 명시할 때만. 기존 기계 동작 테스트(qa, qa-cut, qa-v3, qa-ribbon, qa-polish, qa-width, qa-result)는 시작 때 호환 모드를 명시하도록 바꿨다.
- **접촉 vs 절삭 분리**: 스냅샷에 `isBladeContacting`(날 엣지가 현재 표면에 닿았는가: probe.gap ≤ 0.75, 깎인 홈 포함)과 `isPeeling`(이번 프레임에 새 껍질이 벗겨졌는가)을 따로 노출. 종료 판정은 접촉만 본다(껍질·점수·제거율 무관). `finish()` 는 PLAYING 일 때만 한 번 실행(중복 방지).
- **개발용 디버그(#debug)**: state · fruit · contacting · peeling · 접촉 거리 · 이탈 시간/150ms · 칼 위치·각도 · qa 모드, 접촉 후보점(날에서 표면 쪽으로 가장 깊은 점) 십자 표시.
- **검증**: tools/qa-end.js — 제품 기본 조건(setLegacy 없음, 일시정지·시간 스텝 없음, 클릭 + 실제 키보드, rAF 프레임 기록)으로 4종 × 9상황.

- **원인**: 화면 전환용으로 넣었던 `.screen.active` 의 opacity 0→1 fade(160ms). 모든 화면은 실시간으로 도는 3D 스테이지 캔버스(플레이 크기의 사과·칼) 위에 덮이는 구조라, 화면이 투명한 동안 스테이지의 큰 사과가 비쳐 "크게 나타났다가 정상 크기로" 보였다(fade 도중 고정해서 실측: 빨간 화소 28,592 vs 정상 ≈ 5,800, 사과 214×184px).
- **수정**: fade·keyframes 삭제(새 애니메이션·전체 페이드인 없음). 메인·선택·결과 화면이 켜져 있는 동안 3D 스테이지를 숨김(`.app.screen-on #stage { visibility: hidden }`, main.js `show()` 가 클래스 토글, 초기 HTML 에도 `screen-on`). INTRO 미리보기는 초기화(에셋·과일 선택·모델·레이아웃)가 끝난 뒤 한 번만 그린다(`bootReady`) — 그 전엔 빈 프레임, `?fruit=` 링크로 열어도 사과가 먼저 나왔다가 바뀌지 않는다.
- 검증: tools/qa-boot.js — CDP 스크린캐스트로 첫 프레임부터 캡처, 7가지 상황(첫 접속·F5·강력 새로고침·캐시 없음·모바일 DPR3+CPU 4배·느린 네트워크·과일 선택 후/공유 링크).

## 점수 전면 재설계 (2026-10-19)
- **이전 공식이 낮았던 원인**: ① 제거율 구간 상한(<5% 20점·<15% 45·<30% 65·<50% 85) ② 정확도·연속성 가산이 제거율 60% 까지 비례로 깎임(Q_FULL_PEEL) ③ 껍질 항도 (0.5+0.5×정확도)로 한 번 더 깎임 → 과육 손실 한 번이 3중 감점 ④ 제거율이 선형 가중이라 전부 벗겨야 고득점.
- **신규(scoring.js 한 경로)**: score = coverage × quality × fleshMult. coverage = 100×min(1, 제거율/92%)^0.5(비선형), quality = 1 − (1−정확도)×0.30 − (1−연속성)×0.15, fleshMult = 과육 손실 구간 승수(8%까지 1 → 15% 0.90 → 25% 0.65 → 40%+ 0.50). 정확도 = 100 − 구간 감점(0~3% 1%당 2점, 3~8% 4점, 8~15% 6점) × 낭비 계수(손실 ÷ 제거한 껍질 층 부피). 상한은 의미 없는 플레이만: 유효 절삭 미달(제거 3% 미만 또는 경로 15cm 미만) 15점, 손실 25% 이상 45점. 값은 전부 config.SCORE.
- 효과(사과, 같은 입력): A 88→98 · B 73→88 · C 60→76 · D 46→67 · E 23→45 · F 17→28 · G 9→11. 자동조종 실플레이: 1.5× 깊게 65→94, 40% 59→68, 25% 37→51. 평가 문구는 그대로.
- 검증: tools/qa-score.js (신규=실제 코드, 이전 공식은 스크립트에 내장).

## 오이 → 용과 교체 + 용과 외형 재제작 (2026-10-19)
- **교체**: 4번째 과일 오이(cucumber)를 용과(dragonfruit)로 교체. config key·asset path(`assets/dragonfruit_unpeeled.png`·`dragonfruit_peeled.png`)·선택 state·결과 문구("용과 깎기 완료!"/"내 용과 저장")·공유 링크(`?fruit=dragonfruit`)·테스트까지 오이 참조 제거(저장소 전체 grep 0건).
- **크기**: previewScale 1.00 · playScale 1.03. 시작값(0.95/0.98)은 불투명 실루엣 면적이 사과의 0.89배라 약간 키웠다(면적비 사과 1.0 · 배 1.16 · 키위 0.46). 크기 기준 길이는 돌기를 뺀 분홍 본체(sizeLongest).
- **본체**: 원본 PNG 의 분홍 본체 윤곽(돌기 제외)을 반폭² 다항식으로 피팅해 회전체 모델을 만든다 — 위가 뾰족하고 아래가 둥근 물방울형(높이 736 · 최대 폭 578px, 55% 지점이 가장 넓음). 판정은 이 본체 표면 기준.
- **잎 돌기**: 원본의 잎 11장(밑동 중심·폭·팁)을 PNG 에서 읽어(build-assets.js READ) 3D 장식 메시로 만든다. 밑동이 넓고 끝이 뾰족한 로우폴리 불꽃(가운데 접힘), 색 단계(밑동 분홍→노랑 171,159,59→초록 115,142,43)는 PNG 실측. 앞면 11장은 PNG 와 같은 자리, 뒷면 4장. 잎은 판정에 관여하지 않으며, 밑동이 붙은 표면 셀이 하나라도 벗겨지면 사라진다.
- **씨앗**: 과육 색 셰이더에서 3D 점 패턴(과일 로컬 좌표, 셀 9px · 확률 0.85 · 반지름 1.4~2.2)을 과육 가중치(pt)에만 적용 — 껍질·잎·리본에는 없고, 과일과 함께 회전하며, 깊이 파면 파인 표면을 따라 점의 자리가 바뀐다. 원본 PNG 대비 점 지름 ≈ 2% · 면적비 1.3%(게임 1.6%).
